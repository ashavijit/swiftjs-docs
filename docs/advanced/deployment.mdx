# Deployment

SwiftJS is designed for modern infrastructure. Whether you are deploying to a traditional VPS, a containerized environment (Docker), or an Edge runtime, this guide covers the best practices.

## Environment Preparation

Before deploying, ensure you have set your production environment variables.

```env
NODE_ENV=production
PORT=3000
DATABASE_URL=...
JWT_SECRET=...
```

## Deployment Options

Select your target environment to see specific instructions and configurations.

<Tabs items={["Docker", "PM2 / VPS", "Edge Runtimes"]}>
    <Tab>
      ### Docker (Recommended)
      Docker ensures consistency across development and production.
      
      ```dockerfile
      FROM oven/bun:latest as builder
      WORKDIR /app
      COPY package.json bun.lockb ./
      RUN bun install --frozen-lockfile
      COPY . .
      RUN bun run build
      
      FROM oven/bun:slim
      WORKDIR /app
      COPY --from=builder /app/dist ./dist
      COPY --from=builder /app/package.json ./package.json
      
      CMD ["bun", "dist/app.js"]
      ```
    </Tab>
    <Tab>
      ### PM2 (VPS)
      For traditional VPS deployments without Docker, use PM2 for process management.
      
      ```bash
      pm2 start dist/app.js --name "swift-api" -i max
      ```
    </Tab>
    <Tab>
      ### Edge / Serverless
      SwiftJS provides native adapters for Edge runtimes.
      
      ```typescript
      // Cloudflare Workers
      import { Swift } from 'swiftjs-core';
      import { CloudflareAdapter } from '@swiftjs/adapter-cloudflare';
      
      export default new Swift({ 
        adapter: new CloudflareAdapter() 
      });
      ```
    </Tab>
</Tabs>

## Production Hardening

Follow these steps before going live to ensure your SwiftJS application is secure and performant.

<Steps>
  <Step number="1" title="Environment Configuration">
    Set `NODE_ENV=production` and ensure all secrets are loaded from a secure environment variable provider.
  </Step>
  <Step number="2" title="Enable Optimizations">
    Use the `compression()` and `rateLimit()` middlewares. Ensure **Context Pooling** is enabled (default) for high-load handling.
  </Step>
  <Step number="3" title="Health & Monitoring">
    Expose a `/health` endpoint and integrate with Prometheus or OpenTelemetry for real-time observability.
  </Step>
  <Step number="4" title="Security Audit">
    Check for SQL injection vulnerabilities (if using raw queries) and ensure all inputs are validated via **Zod schemas**.
  </Step>
</Steps>

[!IMPORTANT]
Always deploy behind a reverse proxy (like Nginx, Traefik, or Cloudflare) to handle SSL/TLS termination and provide an additional layer of security.
