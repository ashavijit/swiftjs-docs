# Advanced Features

SwiftJS goes beyond basic routing and middleware, offering robust solutions for production needs.

## Observability

SwiftJS has built-in observability primitives.

### Health Checks

Expose health endpoints easily.

```typescript
app.get('/health', () => ({
  status: 'healthy',
  timestamp: new Date().toISOString(),
  uptime: process.uptime(),
}));
```

### Metrics (Upcoming)

Future versions will include Prometheus-compatible metrics export for request stats, event loop lag, and memory usage.

## Background Jobs

For long-running tasks, don't block the request handler.

### In-Memory Queue (Simple)

For simple use cases, use `setImmediate` or standard Promises, but be aware these don't survive restarts.

```typescript
app.post('/email', async ctx => {
  // Respond immediately
  ctx.status(202).json({ status: 'queued' });

  // Process in background
  setImmediate(async () => {
    try {
      await sendEmail(ctx.body);
    } catch (err) {
      ctx.logger.error('Email failed', err);
    }
  });
});
```

### Job Queue (Recommended)

For production, integrate with Redis-based queues like BullMQ.

```typescript
import { Queue } from 'bullmq';

const emailQueue = new Queue('email');

app.post('/email', async ctx => {
  await emailQueue.add('send', ctx.body);
  return { status: 'queued' };
});
```

## Real-time APIs

### WebSockets

Native WebSocket support is planned for v1.0. Currently, you can use libraries like `ws` or `socket.io` by attaching to the underlying server.

```typescript
import { WebSocketServer } from 'ws';

const app = createApp();

app.listen().then(server => {
  const wss = new WebSocketServer({ server });

  wss.on('connection', ws => {
    ws.on('message', msg => {
      ws.send(`Echo: ${msg}`);
    });
  });
});
```

### Server-Sent Events (SSE)

You can easily implement SSE with SwiftJS.

```typescript
app.get('/events', ctx => {
  ctx.res.setHeader('Content-Type', 'text/event-stream');
  ctx.res.setHeader('Cache-Control', 'no-cache');
  ctx.res.setHeader('Connection', 'keep-alive');

  const interval = setInterval(() => {
    ctx.res.write(`data: ${new Date().toISOString()}\n\n`);
  }, 1000);

  ctx.req.on('close', () => clearInterval(interval));
});
```

## Database Integration

SwiftJS is ORM-agnostic. We recommend fully type-safe ORMs.

### Prisma

```typescript
import { PrismaClient } from '@prisma/client';
const prisma = new PrismaClient();

app.get('/users', async () => {
  return await prisma.user.findMany();
});
```

### Drizzle ORM

```typescript
import { drizzle } from 'drizzle-orm/node-postgres';
import { users } from './schema';

app.get('/users', async () => {
  return await db.select().from(users);
});
```

## Deployment

### Docker

SwiftJS apps are easy to containerize.

```dockerfile
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install --production
COPY dist ./dist
EXPOSE 3000
CMD ["node", "dist/index.js"]
```

### Serverless (AWS Lambda)

Use the `swiftjs-aws-lambda` adapter (coming soon) or `serverless-http` to deploy SwiftJS to AWS Lambda.

```typescript
import serverless from 'serverless-http';
import { createApp } from 'swiftjs-core';

const app = createApp();
// ... routes ...

export const handler = serverless(app);
```

### PM2

For traditional VPS deployment.

```bash
npm run build
pm2 start dist/index.js --name my-app
```

## Graceful Shutdown

SwiftJS handles shutdown signals (SIGINT, SIGTERM) automatically when you use `app.listen()`. It stops accepting new requests and waits for pending requests to complete.

You can add custom cleanup logic:

```typescript
app.addHook('onClose', async () => {
  console.log('Closing database connection...');
  await db.disconnect();
});
```

To manually close the server:

```typescript
await app.close();
```

## Clustering

To utilize all available CPU cores, use the `app.cluster()` method. This automatically forks workers and balances the load.

```typescript
import { createApp } from 'swiftjs-core';

const app = createApp();

app.get('/', () => 'Hello from worker ' + process.pid);

if (process.env.NODE_ENV === 'production') {
  // Use all available cores
  app.cluster();
} else {
  // Single process for dev
  app.listen();
}
```
