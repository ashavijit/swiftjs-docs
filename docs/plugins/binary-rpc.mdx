# Binary RPC

SwiftJS includes a high-performance binary serialization layer built on MessagePack. It reduces payload sizes by 30-50% compared to JSON and uses buffer pooling to minimize garbage collection pressure.

## Quick Start

### Server Setup

Register the plugin to enable binary RPC on all routes:

```typescript
import { binaryRpcPlugin } from 'swiftjs-core';

await app.register(binaryRpcPlugin());
```

Or use the middleware directly for more control:

```typescript
import { binaryRpcMiddleware } from 'swiftjs-core';

app.use(binaryRpcMiddleware());
```

### Client Setup

Enable binary mode on the RPC client:

```typescript
import { createClient } from 'swiftjs-core';

const client = createClient<AppRoutes>({
  baseUrl: 'http://localhost:3000',
  binary: true,
});

const { data } = await client.get['/users']();
```

When `binary: true` is set, the client automatically:
- Sends `Accept: application/x-msgpack` header
- Encodes request bodies in MessagePack
- Decodes binary responses back to JavaScript objects

## Content Negotiation

The middleware uses standard HTTP content negotiation:

| Header | Value | Effect |
|--------|-------|--------|
| `Content-Type` | `application/x-msgpack` | Request body is decoded from MessagePack |
| `Accept` | `application/x-msgpack` | Response body is encoded in MessagePack |

If neither header is present, the middleware is a no-op and JSON is used as normal.

## Low-Level API

You can use the encoder/decoder directly for custom use cases:

```typescript
import { encode, decode } from '@swiftjs/core';

const binary = encode({ name: 'swift', version: 1 });
const original = decode(binary);
```

## Buffer Pool

The `BufferPool` class pre-allocates reusable `Uint8Array` buffers to avoid allocations in the hot path:

```typescript
import { BufferPool } from '@swiftjs/core';

const pool = new BufferPool({
  maxSize: 64,
  bufferSize: 16384,
});

const buf = pool.acquire();
pool.release(buf);
```

## Plugin Configuration

```typescript
await app.register(binaryRpcPlugin({
  bufferPoolSize: 64,
  maxBufferSize: 16384,
}));
```

| Option | Default | Description |
|--------|---------|-------------|
| `bufferPoolSize` | `32` | Maximum number of pooled buffers |
| `maxBufferSize` | `8192` | Initial size of each buffer in bytes |

## Fallback Behavior

Binary RPC is fully backward-compatible. Standard browser clients that don't send the `Accept: application/x-msgpack` header will continue to receive JSON responses. This makes it safe to enable globally.

## Supported Types

The MessagePack codec supports all JSON-compatible types:

- `null` / `undefined`
- `boolean`
- `number` (integers up to 32-bit, 64-bit floats)
- `string` (UTF-8)
- `Array`
- `Object` (plain objects)
- `Uint8Array` / `Buffer` (binary blobs)
