# Express to SwiftJS Migration Guide

SwiftJS is designed to feel familiar to Express developers, but with significant improvements in performance, type safety, and architecture. This guide helps you migrate your existing Express knowledge and codebases to SwiftJS.

## 1. Core Differences

While Express is a minimal middleware-focused framework, SwiftJS provides a more robust, "batteries-included" experience with a focus on **Performance-First** architecture.

<Comparison>
  <ComparisonLeft title="Express">
    ```typescript
    const express = require('express');
    const app = express();
    
    app.get('/user/:id', (req, res) => {
      res.json({ id: req.params.id });
    });
    
    app.listen(3000);
    ```
  </ComparisonLeft>
  <ComparisonRight title="SwiftJS">
    ```typescript
    import { createApp } from 'swiftjs-core';
    
    const app = createApp({ port: 3000 });
    
    app.get('/user/:id', (ctx) => {
      return { id: ctx.params.id };
    });
    
    app.listen();
    ```
  </ComparisonRight>
</Comparison>

## 2. Request & Response Handling

In Express, you interact with `req` and `res` objects. In SwiftJS, everything is unified under a single, highly-optimized `HttpContext` (`ctx`).

### Key Changes:
- **Unified Context**: No more passing both `req` and `res`.
- **Direct Returns**: You can return objects, strings, or numbers directly from handlers. SwiftJS handles the serialization automatically.
- **Typed Params**: Route parameters and query strings are part of the context and can be strictly typed with Zod patterns.

## 3. Middleware Architecture

Express uses a linear middleware chain. SwiftJS uses an **Onion Model** with a high-performance **Iterative Runner**.

<Comparison>
  <ComparisonLeft title="Express Middleware">
    ```typescript
    app.use((req, res, next) => {
      console.log('Before');
      next();
    });
    ```
  </ComparisonLeft>
  <ComparisonRight title="SwiftJS Middleware">
    ```typescript
    app.use(async (ctx, next) => {
      console.log('Before');
      await next();
      console.log('After');
    });
    ```
  </ComparisonRight>
</Comparison>

[!TIP]
Because SwiftJS uses `await next()`, you can easily perform actions **after** the handler has executed (e.g., logging response time or post-processing data).

## 4. Routing Strategy

Express routing is regex-based and can become slow as you add hundreds of routes. SwiftJS uses a **Radix Tree Router** for $O(k)$ matching.

<Steps>
  <Step number="1" title="Structure">
    Organize your routes in the `routes/` directory for automatic file-based routing, or use programmatic routing for dynamic needs.
  </Step>
  <Step number="2" title="Define">
    Use the same HTTP verbs (`get`, `post`, `put`, `delete`) you're already familiar with.
  </Step>
  <Step number="3" title="Optimize">
    Take advantage of **Zero-Allocation matching** by using static paths where possible.
  </Step>
</Steps>

## 5. Performance Comparison

Developers moving from Express typically see a **10x - 15x increase in throughput** and a significant reduction in memory usage due to our **Context Pooling** technology.

[!IMPORTANT]
To get the most out of SwiftJS, avoid adding heavy synchronous work in global middlewares. Use Dependency Injection to keep your handlers lean and testable.
